## What shipped

Three installers of the same app, one per flavor, plus the updater manifest.

| Flavor | Asset | Bytes |
|---|---|---:|
| CPU only | `Unsloth_2026.5.2_x64-cpu-setup.exe` | 24,025,140 |
| GPU (CUDA llama.cpp) | `Unsloth_2026.5.2_x64-gpu-setup.exe` | 24,023,266 |
| Universal | `Unsloth_2026.5.2_x64-cpu-gpu-setup.exe` | 24,021,650 |

Each installer carries a 420-byte `.sig`; `latest.json` (1,490 bytes) points at
the **universal** build:

```
https://github.com/GoldodemonINC/unsloth_8X/releases/download/v2026.5.2/Unsloth_2026.5.2_x64-cpu-gpu-setup.exe
```

The work in this release is the Labs picker pass. CMT's base checkpoint and CMT's
dataset rows, and Auto Scale's model field and dataset list, are Hub search fields
with a Hugging Face / Local path toggle that decides how the value is read: a Hub
value is always an `owner/name` repo id, a local value is always a path, so a
relative local directory stays a path instead of being mistaken for a repo. A
pasted `huggingface.co` or `hf.co` page is normalized, including `/datasets`,
`/models`, `/tree/<rev>`, a query string, a fragment and a `.git` suffix; anything
that is not a repository is refused with a reason beside the field and never
replaces the last valid value. Auto Scale's datasets textarea became removable
pills fed by a search-and-add row, so a run can mix local files with Hub ids, and
the planner lists a Hub id as unmeasured rather than downloading it. The Browse
action appears only where a native picker exists, so the web build no longer shows
a button that cannot work.

## How it was built

```bash
python scripts/release_x8_local.py --version 2026.5.2 --variants all \
  --notes-file /tmp/x8-notes-2026.5.2.txt          # build, sign, assemble, upload

# the same publish path, if the build is already staged:
tok=$(printf "protocol=https\nhost=github.com\n\n" | git credential fill | sed -n 's/^password=//p')
GH_TOKEN="$tok" python scripts/release_x8_local.py --version 2026.5.2 \
  --variants all --skip-build --notes-file /tmp/x8-notes-2026.5.2.txt
```

`gh` was not logged in on this machine, so the first run built all three flavors
and stopped at the upload. Nothing was published or partially published: the
script checks credentials before it creates the release. The staged pairs in
`release-out/` were then uploaded with the credential `git` already had, which is
also how 2026.5.1 was published.

The build compiles each flavor separately (`UNSLOTH_DESKTOP_FLAVOR` is a
compile-time value), signs each with `studio/src-tauri/x8-updater.key` (not in the
repository), and stages the pairs in `release-out/` under their published names
before anything is uploaded. Authenticode is skipped locally
(`UNSLOTH_SKIP_AUTHENTICODE=1`); the Tauri updater signature is still generated
and is what clients verify.
